# 每日任务专注计时软件需求说明

版本：V1.0
整理日期：2026年10月17日
用途：交给 Codex 实现 Windows 桌面软件
状态：核心需求已由用户确认；未逐项询问的边界行为在本文标注为“默认规则”。

## 一 开发目标

请根据本文直接开发一个中文的个人任务管理与专注计时桌面软件，并完成必要测试。用户的编程基础有限，交付应便于在 Windows 11 电脑上安装、启动和日常使用。

软件的核心流程为：添加当天任务并设定预计时长 → 用户自己选择何时开始 → 进入只显示倒计时的全屏界面 → 期间可退出全屏查资料，计时继续 → 任务提前完成或超时后，由用户主动结束并勾选完成 → 保存历史和用时统计。

这是独立的本地工具。日常使用必须免费、离线可用，无需账号、AI 模型接口、订阅、云服务器或运行开发助手。开发助手本身的套餐费用与本软件运行费用分开。

## 三 页面和交互要求

### 主界面

主界面包含日期切换、当天任务清单、新建任务入口、当前计时状态以及历史与统计入口。使用中文界面，操作直接，避免让用户配置开发环境或接口参数。

任务行至少展示：任务名称、预计时长、完成状态、优先级、开始或继续计时按钮。备注和子任务可以在任务详情中展开，避免全部挤在清单中。

运行中的任务需要在主界面显示剩余时间或超时时间，并提供“返回全屏”“暂停或继续”“结束本次”“完成任务”操作。返回全屏可以由用户主动点击，无需再次启动计时。

默认规则：优先级提供高、中、低，默认中。用户的拖动顺序持久保存；设置优先级不会擅自改变手动排序。主界面清楚区分未完成与已完成任务。

### 全屏界面

全屏覆盖应用所在的当前显示器，隐藏应用菜单、任务列表、窗口标题栏等界面元素。第一版不要求同时遮盖所有显示器。

全屏中只保留大号计时数字；不显示任务名称、鼓励语、统计图、按钮、任务栏或悬浮面板。不做鼠标移动后弹出控制栏的设计，主要通过快捷键操作。

默认规则：
- 背景使用纯深色，正常倒计时使用高对比度浅色数字。
- 小于一小时显示 MM:SS，一小时及以上显示 HH:MM:SS。
- 超时使用加号和数字，例如 +03:20；颜色可以改变，但不增加文字标签。
- 暂停时数字冻结，可通过降低数字亮度区分；主界面必须明确标注暂停状态。
- Esc 退出全屏，返回主界面；此操作本身不暂停计时。
- 空格键在专注全屏中暂停或继续；普通文本输入框中不得拦截空格。
- 主界面提供可见的返回全屏按钮。首次进入前用简短提示说明 Esc 和空格操作，之后不在全屏中显示提示。
- 普通全屏允许用户切换应用或退出，不做强制锁屏或禁用系统快捷键。

### 完成和结束

“结束本次”与“完成任务”是两个不同动作。

默认规则：
- 结束本次：停止当前计时，保存本次用时，任务保持未完成，以后可以继续。
- 完成任务：停止正在进行的计时，保存用时，并将任务勾选为已完成；未计时的任务也允许用户手动勾选。
- 全屏中提前完成的操作路径为 Esc 返回主界面，再点击完成任务。
- 时间用完不代表任务完成，软件不得自动勾选，也不得自动进入休息或下一项任务。
- 用户取消完成勾选时，保留原来的计时记录，允许继续做。
- 启动其他任务时若已有任务正在计时，应提示先结束或切换；切换时保存原任务用时。同一时刻只允许一个任务计时。

## 四 计时和统计规则

以下是为实现清晰行为补充的默认规则。

### 时间定义

| 指标 | 定义 |
| --- | --- |
| 预计用时 P | 用户为某日某个任务实例设定的总时间预算 |
| 实际用时 A | 该任务所有计时片段的累计运行时长，扣除暂停、关闭软件及电脑休眠时间 |
| 剩余时间 | max(P - A, 0) |
| 超时时长 O | max(A - P, 0) |
| 按时完成 | 任务被用户标记完成，且 A 小于或等于 P |
| 超时完成 | 任务被用户标记完成，且 A 大于 P |

实际用时表示计时器记录的运行时长。退出全屏查资料时仍计入；暂停期间不计入。内部保留秒级或更高精度，不按整分钟累加。

同一任务分多次进行时，预计用时是整个任务的预算，每次继续都从剩余预算接着计时，不重新获得一整段预算。首次开始后，默认固定该实例的预计时长，以保持统计口径；未开始任务仍可修改预计时长。

到零提示默认采用短提示音一次，界面无阻塞地进入超时数字显示。允许在设置里关闭提示音。暂停后继续、退出后重开、重新进入全屏，都不得反复播放同一次到零提示。

例子：任务预计20分钟，先运行7分钟、暂停10分钟，再运行16分钟后结束，则实际用时为23分钟、超时时长为3分钟；暂停的10分钟不计入。

另一个例子：任务预计20分钟，第一次运行10分钟后“结束本次”，第二次继续运行12分钟，则实际用时22分钟、超时2分钟，第二次开始时剩余10分钟。

### 历史和统计

按日期查看任务，任务记录至少包含名称、所属日期、优先级、预计用时、实际用时、超时时长、完成状态、备注和子任务状态。

基础统计包含：
- 所选日期的任务总数和完成数。
- 预计用时合计、实际用时合计、超时时长合计。
- 每个任务的预计与实际用时对比，以及按时完成或超时完成状态。
- 未完成但已经超时的任务仍显示超时，不能被算作已完成。

默认规则：按任务所属日期汇总，历史界面标明这个口径。跨午夜继续运行的任务仍归属原来的日期；不会自动结束、搬移或创建第二个计时器。每日重复任务在新的一天生成独立实例。第一版不要求复杂的周月图表和专注评分。

### 时间可靠性

不能简单依赖“每刷新一次界面就减一秒”。切换窗口、窗口最小化或短暂卡顿后，应显示正确的剩余时间。

系统时间被手动调整时，不应让正在运行的计时突然增减。计时逻辑与界面刷新分开。

默认规则：
- 正常关闭软件时保存进度并暂停，下次打开以暂停状态恢复，等待用户继续。
- 电脑休眠时自动暂停，唤醒后等待用户继续，不把睡眠时间算作专注。
- 异常退出后恢复到最近保存点，恢复为暂停状态；离线关闭期间不计时。
- 运行中至少每5秒保存一次检查点；若异常退出只能恢复最近检查点，应说明最多可能损失的未保存时长。
- 跨午夜、正常关闭和异常恢复都不得重复累加已保存的计时片段。

## 五 重复任务 子任务和数据

### 每日重复任务

每日重复任务采用“重复模板”和“每日实例”分开保存的方式。

默认规则：
- 由用户设置任务名称、预计时长、优先级、备注和子任务模板，并启用每日重复。
- 当天首次打开软件或跨日刷新时，为当天生成一个实例；同一天多次打开不会重复生成。
- 新实例的实际用时为零、状态未完成、子任务未完成；不会继承昨天的计时和勾选。
- 软件关闭时不要求后台运行或定时唤醒。再次打开时生成当天任务，不补造未打开日期的任务。
- 编辑模板影响之后生成的任务，不改变过去的名称、预算和完成记录；修改当天实例只影响当天。
- 停用模板只停止之后的自动生成，历史记录保留。
- 昨天未完成的任务留在昨天的历史中，不自动搬到今天，也不与今天的新实例合并。

### 子任务与排序

默认规则：
- 子任务第一版只需一层，包含名称、勾选状态和顺序，不单独启动计时器。
- 父任务统一拥有预计时长和计时记录；子任务不重复计入任务总数及用时合计。
- 子任务全部勾选后，不擅自结束正在运行的计时器，由用户确认父任务完成。
- 父任务仍有未完成子项时，用户点击完成应得到确认提示，由用户决定是否完成父任务。
- 备注支持普通多行文本，无需富文本编辑器。
- 当天任务拖动排序后关闭重开，顺序仍然保留。

### 数据保存

默认规则：
- 自动保存在当前 Windows 用户的数据目录，不保存在易被覆盖的程序安装目录或临时目录。
- 任务、历史、模板、设置与计时记录都在本地保存，不上传，不要求联网。
- 使用稳定的唯一标识关联任务、模板和计时记录，不能仅靠任务名称关联。
- 历史任务保存当时的快照，不能随重复模板修改而变化。
- 提供手动导出与导入备份入口，备份应覆盖历史、模板、设置和计时数据。导入前校验，导入失败不得损坏原数据。
- 删除任务需要确认。有计时记录的任务默认归档隐藏并保留统计；若提供彻底删除，必须说明将移除哪些记录。
- 更新程序时保留用户数据，并在必要的数据格式升级前备份。
