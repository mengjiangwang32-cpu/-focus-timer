# 开发与构建

## 项目结构与技术方案

```text
electron/main.js        桌面生命周期、单实例、受限 IPC、全屏、休眠与备份对话框
electron/preload.cjs    contextBridge，仅暴露业务方法
electron/store.js       本地校验、同步落盘、原子替换与损坏恢复
src/core/model.js      模型、日期、统计、备份全图校验
src/core/engine.js     可注入单调／日历时钟的计时和任务状态机
src/App.jsx            中文任务、历史、模板、设置及全屏页面
src/styles.css         本地样式，无联网素材
tests/                 Node 测试和真实 Electron 桌面自动化
windows/               包内使用说明与快捷方式脚本
assets/                原创 SVG、PNG 与多尺寸 ICO
```

使用成熟的免费开源桌面组件。计时由 Electron 主进程独占，`performance.now()` 单调时钟与用于显示日期的系统时钟分离。`powerMonitor` 的 suspend 在睡眠前保存并暂停；恢复不自动继续。渲染器只显示主进程状态，250ms刷新，不靠“刷新一次减一秒”。运行检查点间隔约1.5秒，正常调度下不到2秒保存一次；所有业务操作立即保存。每个计时片段只维护一个累计值，关闭与恢复不重放已保存片段。

模板、任务实例、子任务和计时片段均使用 UUID；实例保留历史快照。每日只检查今天，不补造离线日期。JSON schemaVersion=1，完整验证 ID 唯一性、引用、日期、用时、布尔值和活动片段。导入先验证整份数据、保留旧数据再替换。当前没有数据库服务、原生编译插件或云依赖。

渲染器关闭 Node 集成、启用上下文隔离和 sandbox；仅接受主窗口主框架 IPC，禁止新窗口、导航与权限请求。成品加载本地文件，CSP不允许远程脚本、字体或图片。Linux 测试参数 `--no-sandbox` 仅用于受隔离的 CI 测试，不用于交付启动脚本。

## Windows 重新构建（推荐）

安装 [Node.js 24 LTS](https://nodejs.org/)，将源码解压到例如 `C:\Projects\shiguang-focus`。在该文件夹打开 PowerShell，完整运行：

```powershell
Set-Location 'C:\Projects\shiguang-focus'
npm ci
node node_modules/electron/install.js
npm test
npm run build
npm run test:ui
npm run dist:win
npm run pack:win
```

产物在 `release`：

- `Shiguang-Focus-1.0.0-Windows-x64.exe`：NSIS 安装器，按用户安装，可选择目录，创建桌面和开始菜单快捷方式，卸载不删除用户数据。
- `Shiguang-Focus-1.0.0-Windows-x64.zip`：免安装完整文件夹。

开发窗口使用 `npm run dev`；已构建后用 `npm start`。首次下载依赖及打包工具需要网络；成品运行不需要网络。锁文件已保留，采用 `npm ci` 复现依赖版本。界面和主进程修改后应重新构建与打包。

## 云环境与 Linux

直接使用 `/workspace/-focus-timer` 的现有检出目录。每次云任务已经隔离，无需另外创建 Git worktree。

```bash
cd /workspace/-focus-timer
export npm_config_cache=/workspace/.cache/npm
export XDG_CACHE_HOME=/workspace/.cache
export electron_config_cache=/workspace/.cache/electron
export ELECTRON_BUILDER_CACHE=/workspace/.cache/electron-builder
export NODE_USE_ENV_PROXY=1
npm ci
node node_modules/electron/install.js
npm test
npm run build
# 有显示服务时：
npm run dev
# CI 中已有 Xvfb 时：
xvfb-run -a npm run test:ui
```

`NODE_USE_ENV_PROXY=1` 使 Node24 的下载器沿用现有 HTTPS 代理；不关闭 TLS 校验和产物校验。Linux桌面验证需要 X11/Xvfb及 Electron运行库；本次使用 Debian Xvfb，测试本身运行真实 Electron 窗口。无显示服务的 Linux 可先运行 Node测试与 Vite构建，但不能把它称作桌面实测。

Linux 可交叉打包 Windows ZIP。NSIS 在 Linux 还需要兼容的 Wine；本次云机器的 Wine 出现 ntdll 加载失败，随后转到 GitHub Windows runner，已成功完成安装器和 ZIP 构建发布。[成功的发布流程](https://github.com/mengjiangwang32-cpu/-focus-timer/actions/runs/39011903448)同时执行了核心与桌面测试。Windows 本机打包无需 Wine。

所有本地打包命令显式指定 `--publish never`，只生成文件，避免 electron-builder 根据 CI 环境自行发布或要求额外令牌。GitHub 工作流在打包和测试通过后，用该仓库自动提供的 `GITHUB_TOKEN` 独立创建发布版本，不需要用户提供个人访问令牌。下载目标为 GitHub及其 release-assets、npm registry；安装依赖与本地打包不要求 GitHub 写入凭据。

## 备份、升级和打包注意事项

正式数据目录固定为 `app.getPath('appData')/ShiguangFocus/data`；不要修改 appId 或数据路径以免未来版本无法找到旧数据。测试通过非打包模式专用的 `FOCUS_TEST_DATA` 覆盖目录，不写入正式数据。打包模式忽略该变量。

未来 schema 升级必须先写出可恢复的迁移前备份，再执行并校验升级结果；未知版本目前拒绝加载，绝不静默重置。导入上限20MB，单任务最多100个子项，名称200字，备注20000字，单任务预算最长7天。

未配置商业代码签名证书，因此包为未签名发布。`signExecutable=false` 保留图标、版本等资源写入，只关闭签名。Electron原始下载、npm完整性、打包工具的校验仍然启用。

## 开源来源

没有复制其他番茄钟或任务软件的业务实现。由于本需求的累计预算、用户完成、休眠与历史快照规则具有明确差异，核心逻辑独立实现并测试。参考了官方 API 和已安装工具的类型定义：

- [Electron](https://github.com/electron/electron)：桌面窗口、全屏、powerMonitor、IPC，MIT；Chromium和相关组件的许可证随 Electron 包保留。
- [React](https://github.com/facebook/react)：本地 UI，MIT。
- [Lucide](https://github.com/lucide-icons/lucide)：界面图标，ISC。
- [Vite](https://github.com/vitejs/vite)：构建工具，MIT。
- [electron-builder](https://github.com/electron-userland/electron-builder)：Windows 打包、NSIS及Wine工具集，MIT。
- [Playwright](https://github.com/microsoft/playwright)：桌面自动化，Apache-2.0。

源码采用 MIT，使用自绘应用图标。生产依赖审计为0项漏洞；开发打包链的审计结果可能随 npm 数据库变化，应在正式持续发布前复核。
